# 进阶（给懂技术的你）

本文讲清 Life OS 的**入口分层**：不同 agent 怎么找到并遵守包根的 `AGENTS.md`。核心目标只有一个——让 agent 以包根为工作目录、读到入口规则、按规则工作。

---

## 硬约束：AGENTS.md 有 8000 字符上限

WorkBuddy 对入口文件会**截断超出 8000 字符的部分**，多余内容直接丢失。

因此：**不要把细节堆进 `AGENTS.md`**。它放两样东西——**规矩本身**（读法约定、写权限、隐私边界，这些必须被 agent 第一眼看到）和**指路**（去哪读更细的东西）。而重资产一律外置：访谈逻辑在 `_skills/life-os/`（板块范围与分流规则在 `references/domains.md`、理论术语释义在 `references/glossary.md`、只读扫盘在 `references/scan.md`），记录模板在 `_template/`，术语表在 `CONTEXT.md`，设计决策在 `docs/adr/`。目前入口文件约 2400 字符，离上限还有充足余量——保持这个量级。

---

## 入口三层

### 自动层：Codex 与 WorkBuddy

这两个 agent **默认就会读包根的 `AGENTS.md`**，无需任何配置。只要以本包为工作目录启动，入口即生效。

### 配置层：Gemini CLI

Gemini CLI 默认只认 `GEMINI.md`，不认 `AGENTS.md`。为此包内已提供 `.gemini/settings.json`，内容为：

```json
{"contextFileName": ["AGENTS.md"]}
```

当 Gemini CLI **以包根为工作目录**启动时，这份配置会自动生效，让它改读 `AGENTS.md`。

> 注意：各版本 Gemini CLI 的配置键名可能是 `contextFileName`，也可能是嵌套的 `context.fileName`。若上面的配置无效，请查你所用版本的官方文档确认键名。
>
> 包内另有一份 `GEMINI.md` 作为兜底——它**只有一句话**：「请读 `AGENTS.md`」。它**不重复** `AGENTS.md` 的任何内容，这是刻意的：重复的规则一定会漂移，两份不一致时没人知道该信哪一份。**因此不要把任何规则写进 `GEMINI.md`。**

### 兜底层：豆包电脑版、智谱清言、Trae 等

这类 agent 既不认 `AGENTS.md`，也没有可配置入口。用户需要**手动粘贴一句起步指令**：

> 请读 AGENTS.md，并严格按它的规则工作。

把这句话连同包根目录一起给到 agent 即可。

---

## 加载顺序：不要放 CODEBUDDY.md

WorkBuddy 只加载**第一个命中**的指导文件，顺序为：

`CODEBUDDY.md` → `.codebuddy/CODEBUDDY.md` → `AGENTS.md`

也就是说，如果包里出现了 `CODEBUDDY.md`，WorkBuddy 会读它而**跳过 `AGENTS.md`**，导致入口规则错乱。因此：**本包禁止放 `CODEBUDDY.md`**，确保 `AGENTS.md` 作为唯一入口被加载。

## 可选理论包（theory packs）

`_skills/life-os/references/theories/` 下放着三套**可选理论包**：`sunxue.md`（孙学）、`boji.md`（薄肌）、`huangmao.md`（黄毛）。

- 它们是**外置参考资料**，随包分发，但**默认不注入**。访谈阶段 0.5 会问用户要不要；用户可一套都不要。
- 每套包内是「候选条目 + 可判定化写法 + 明确排除内容」。注入时逐条经用户确认，落盘条目带来源标注并注明**归属层级**（如 `〔源：孙学 · 书 PART4-4｜本人主张〕`）。
- 注入规则（含落点表、排除清单）在 `references/theories/adaptation.md`；术语的「**一句人话 + 一个例子**」在 `references/glossary.md`（**术语释义只在那里定义**，理论包里只给可判定化写法与落点）。
- **想加自己的理论包**：照现有 `theories/*.md` 的结构新建一个文件即可——开头写出处与性质声明，正文给「候选条目（含可判定化写法）」与「明确不注入的内容」。不要与既有包重名。
- **一手来源（各自独立，不得混用）**：三套包的来源彼此独立——孙学＝孙宇晨《这世界既残酷也温柔》（九州出版社 2017）与音频课《财富自由革命之路》（2016 喜马拉雅）；薄肌＝邵艾伦本人的开源项目「薄肌理论 2.0」（github.com/XiaoSiKe/shao-alan-operating-system），**不是孙宇晨的**；黄毛＝第三方网络技能文档《黄毛决胜法 — Alpha Game Mastery》（github.com/0xcii/alpha-game-mastery），与两位受访者都无关。那次访谈的逐字稿只作孙学的旁证（**薄肌、黄毛都不取自访谈**），存于 `.workbuddy/research/`，不进交付包。
- **归属层级**：每套包的条目都按「归属层级」标注——**本人主张**／**项目推演**／**第三方文档**——落盘时不得把推演或第三方文档写成人物原话，被标为「项目推演」的内容须同时注明「这不是本人提出的」。依据见 `docs/adr/0014-theory-packs-multi-source-attribution.md`。
- **理论源件**：每套理论包背后还有一层「理论源件」——完整参考文本的**过滤版全文**，放在 `_skills/life-os/references/theories/sources/`，随包分发、供 agent 深挖与人工阅读。它**不是注入单位**：注入仍以理论包内的候选条目为最小单位，源件只是查阅用的底稿。
- **三条硬红线**：理论包随包分发的内容受三条硬红线约束——**政治敏感内容**、**外貌与性别物化表述**、**投资标的／具体金额／变现路径／加杠杆操作**——一律不进包（只留项目存档）。依据见 `docs/adr/0013-theory-content-redlines.md`。

> **载体限制**：若用户只是把 `_skills/life-os/SKILL.md` 整段复制进对话框、读不到 `theories/` 下的文件，agent **不得凭印象编造理论内容**——要么请用户把对应 `<包名>.md` 贴进来，要么直接跳过该环节。编造一个理论比不做理论包危险得多。

## 推荐 agent（按适配度，不含邀请信息）

**不提供邀请码、不提供链接、不宣称任何「邀请返利」**——这类信息变动快、必须现场核实，写进文档必然过时或失真。

**大陆可直接使用（推荐起步）**

- **WorkBuddy**（腾讯）：自动层，桌面版默认读 `AGENTS.md`，右键即可打开本地文件并写回。
- **豆包电脑版**「办公任务」模式：兜底层，授权后能读文件夹并写回，免费；需手动粘贴起步指令。
- **智谱清言** PC 客户端：兜底层，可挂载本地文件夹做跨文件分析。
- **Trae** 国内版：兜底层，免费，Agent 能读写项目文件。
- **通义灵码 / Qoder CN**（阿里）：原生读 `AGENTS.md`，订阅价格以官方页面为准。

**需要额外网络条件（大陆不直接可用，不适合新手起步）**

- Codex CLI · Gemini CLI · Claude Code · Cursor · Windsurf

**手机端**

普通手机 AI 对话 App（豆包 / Kimi / 元宝 / 通义 的手机版）**全部不合格**——只能上传单个文件对话，不能读写目录。手机上目前能用的是 **OpenMinis** 这类自带文件系统的 agent。

---

选哪个，只看两条：**能不能读写本地文件**（唯一硬门槛）、**大陆能不能直接用**。其它都是次要的。

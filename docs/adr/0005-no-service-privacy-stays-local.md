# 系统不提供任何线上服务，永不接收用户数据

本可以做一个网页版访谈来换取零门槛，但放弃了。一旦服务端碰到用户的人生档案（健康、财务、关系），费用与隐私责任就随用户数线性放大，而收益端并不因此变好——这套系统的价值在文件结构和访谈质量里，不在托管能力里。因此只以离线压缩包的形式分发：提示词、模板、使用文档，用户在自己的机器、自己的 AI 账号里跑完访谈，数据从头到尾不离开本地。

代价是必须承认失去了所有服务端能力：没有账号、没有跨设备同步、没有使用统计、**没有主动触达**（系统只能被动等用户开口，无法定时推送）。这也意味着「绝不接收数据」是一条硬约束，不能因为某个功能很诱人而破例。

## 补充：可选「只读扫盘」也在同一约束之下

访谈期新增了一个可选的只读扫盘（规则见 `_skills/life-os/references/scan.md`）：经用户同意后，agent **只读**本机常见的 AI 目录与项目说明文件，把结论提炼成「候选画像」，供用户逐条确认。

它不构成对「绝不接收数据」的破例。读的是**用户自己机器上、本来就在本地的文件**；结论**只在本机内使用**；**不外发、不发起任何出网请求**；原始文本**不复制进包**；**逐条经本人确认**才落盘。凭据密钥与他人资料明确排除在外，读到也不写、只提示用户自行处置。换句话说，这一步没有引入任何新的数据接收方——机器还是那台机器，只是让 agent 少问几个已知的问题。拒绝扫盘不影响访谈流程。

# 理论包是外置参考，默认不注入，候选非既成

**理论包是候选来源，不是实例内容；默认关闭、必须询问、逐条确认、可整体摘除。**

访谈开始前，agent 会问用户是否注入几套**可选理论包**（当前三套：孙学、薄肌、黄毛）。这些包以纯文本参考文件放在 `_skills/life-os/references/theories/`，**随交付压缩包一并分发**，但默认不激活。包内的条目一律以「待确认的候选」呈现，只有用户逐条点头的才写进实例。

具体规则：

1. **外置、随包分发、默认不激活。** 理论包是参考资料，不是实例数据。它们的存在不改变「实例里只有用户自己的东西」这条底线。
2. **默认关闭，且必须询问。** 访谈的阶段 0.5 专门问一次，用户**可以一套都不要**。不问就注入、或默认打开，都违反此条。
3. **候选非既成。** 每条落盘前必须经用户确认，并改写为**可判定**的句子（能回答「违反了没有」）。理由：条目一旦进 `principles.md`，就成了 agent 以后替用户做判断的依据，而它们大多是某个人的**未经验证的主张**。
4. **必须可追溯。** 每条落盘条目带来源标注，形如 `〔源：孙学 · 书 PART4-4〕`。未确认的进 `meta/profile.md` 的 `## 待定`。
5. **明确排除。** 投资／Crypto 标的／资产配置／具体金额／变现路径、以「吸引异性／后代质量」为动机的表述、对特定群体的贬称等，一律不进任何板块（清单见 `_skills/life-os/references/theories/adaptation.md` 第四节）。
6. **可整体摘除。** 用户随时可以要求摘掉某个包，agent 依来源标注精确删除其带来的条目，并把这次摘除记入流水。

**为什么不设「AI 掌舵者」这一项。** 曾考虑把「让 AI 主导决策」作为一个可选元设定。经讨论剔除：受访者那句「100% 相信 AI」更多是一种夸张修辞，而「主动给建议、给结论而非罗列选项」本就是这个系统对 agent 的默认期待，不需要额外开关；把它做成可选项反而会诱导用户交出判断权，与写权限边界冲突。故当前可选理论包为三套。

配套边界：板块没有激活，对应理论条目就不落盘——**理论不能成为逼用户开板块的理由**。

# 访谈期允许 agent 代录画像（写权限的唯一例外）

**画像文件平时只由人写、agent 只读；但首次访谈期是正式例外——agent 可以代录本人口述。**

起因是包内四处口径互相矛盾。一边说「不能写」：`AGENTS.md` 的写权限节写「绝不写 `profile.md`」，`meta/profile.md` 与 `_template/profile.md` 都写「只有人能写／禁止修改」。另一边说「必须写」：`_skills/life-os/SKILL.md` 的映射表要求阶段 1 第 1–7 题落进 `meta/profile.md`、阶段 4 第 16 题落进 `<domain>/profile.md`，`references/mapping.md` 的生成清单更直接写着「`meta/profile.md` ← 覆盖，写入他的真实信息」。用户实跑一次访谈时因此撞上规则冲突；他按「访谈期 agent 代录」处理，并在文件末尾注了依据。**做法是对的，缺的只是规则里没有这条例外**——所以本次把它立成正式条款，而不是改用户的做法。

条款的边界有三条，缺一不可：

1. **何时生效**：包**尚未访谈过**（根目录没有任何板块目录）**且**正在跑访谈流程。
2. **附带的义务**：落盘前必须把要写的内容**整体复述**并经本人确认（铁律五已有此要求，此处显式绑定）；写入的画像文件末尾必须注明「**由 agent 代录本人口述**」。
3. **何时失效**：访谈结束——板块目录已生成——立即回到「画像只读」，此后 agent 不得再改任何 `profile.md`。

**为什么这条不与「agent 只读画像」矛盾。** 那条规则要防的是：agent 在用户不知情、未确认的情况下，把推断或编造的东西写进本该由本人负责的稳定事实，日后被当成判断依据。访谈代录不满足这个风险条件——内容逐条来自本人口述，落盘前经本人整体确认，文件里留有代录标注，且只发生在首次访谈这一个窗口内。换句话说，例外放宽的是「谁的手」，不是「谁的信息」；窗口一关，规则立刻复原。

配套：工单 08 的可选只读扫盘也受这条边界约束——扫盘结论只能作为「候选」，同样要逐条经本人确认才落盘，并同样负有代录标注义务。窗口之外（包已访谈过）扫盘不重复进行，也就没有可写入的地方。

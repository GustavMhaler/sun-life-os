# 访谈分两层，并要求「答案 → 文件」的确定性映射

访谈最初有两种极端做法：一份全固定问卷（可复现、好验证，但「启发式」就没了，每个人拿到的实例一样厚），或让 agent 完全自由追问（能挖得很深，但同一个人的两次访谈产出不同，模板无从验证，也无法判断是访谈质量问题还是模型随机性）。

决定走中间：**固定核心问卷**（15–25 题，覆盖「你是谁 / 你要什么 / 你的硬约束是什么」三类，必答）**+ agent 按回答追加追问**（深度自适应）。并加一条硬约束：必须定义「答案 → 写进哪个板块的哪类文档」的**确定性映射表**。否则十个人跑完得到十种结构，「同一套系统」这个承诺当场作废。代价是放弃了对极端个案的完全适配能力——一个情况特别复杂的人，核心问卷可能兜不住他的全部需求。

## 补充：为什么保留并用「具体经验」改写两处难答的问题

阶段 4 的四个通用问（现在记为 A–D）里，C（这个板块的硬约束 / 什么算失败）与 D（有没有只有你自己知道的背景）是**判据来源**，不是凑数：C 的产出落进板块 `principles.md`，是 agent 以后替用户**踩刹车**的依据——没有它，agent 只能给通用建议；D 的产出落进板块 `profile.md`，作用是**防误判**——用户的处境里有外人看不见的约束，不写下来，agent 的建议会撞在看不见的墙上。

但用户实跑时反馈这两问「有点难回答」，还追问过「这两问的要求是从哪来的」。原因清楚：**「硬约束」「失败判据」「只有你自己知道的背景」是给设计者看的概念，不是给本人听的问句**——直接把抽象名词抛给受访者，他无从下口。同一次反馈里，阶段 2 的「有哪些事你无论什么情况下都不做」属于同一类毛病。

处理方式是**改写而非删除**：先说明用途（C 供踩刹车、D 防误判），再从**具体经验**切入（「过去有没有一次，你事后觉得这事本不该做」「过去有没有人给过你明显不对的建议，当时他漏了什么背景」），并在追问规则里配好角度。之所以不删：删掉 C 就没有原则可落、删掉 D 就没有画像可落，这套系统的价值核心（原则）会直接塌掉——**问题出在问法，不在问题**。两问答不上来时允许留待定，与其余问题同一条规则。

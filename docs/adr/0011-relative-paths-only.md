# 包内所有路径都是相对路径，不写死解压位置

用户的解压位置无法预测——Windows 桌面、Mac 的下载目录、Linux 的 home、或者手机沙盒里的工作区，而且他们会改名、会移动、会同时留几份备份。任何写死的绝对路径在他改一次文件夹名之后就全线失效，而失效方式是静默的：agent 找不到文件，然后凭猜继续干活。

因此包里的一切内部引用都写相对路径，并且**以「包根目录就是工作目录」为前提**。这带来一个必须在文档里讲清、且最不能含糊的动作：**启动 agent 时要把工作目录设成这个文件夹**——否则 agent 从别处启动，相对路径全部落空。

判定标准也据此定：一个包是否被正确放置，看的不是它在哪里，而是 agent 能否以它为工作目录打开。
